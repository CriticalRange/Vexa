# Megabonk GL thunk loader and frame telemetry

The Android libGL thunk generator previously tried `dlopen("libGL.so.1")` and then an app-private sibling path before Android GLES fallbacks. On this device the sibling was a stale separate AArch64 FEX libGL host thunk, SHA-256 `56e68fb7f07953c8696f02105a9024ae3dda306d40d3d32933357b84876fb6e6`, and was mapped alongside the current `libGL-host.so`. This is unsafe ambiguity between versions; seeing two libraries did not alone prove which functions rendered frames.

For Android libGL only, generator initialization now selects system `libGLESv3.so` then `libGLESv2.so`, without using app-private `libGL.so.1`; non-Android loader and other thunk types retain their prior path. Rebuilt Windows thunkgen and Android 64/32-bit GL host libraries, staged both and built an experimental APK. APK SHA-256 `3bbfd93c5b50c0d2ee279e72207892e5dd380418081e284e8c6ff87238715006`; loaded GL-host 64 SHA-256 `41fe3dbe8af7334fe2e8a2c880a637de22caee592987496dc3ecf30cac0d2287`, runtime stamp `vexa-graphics-1:b077bab1cf342d98`. Existing FEX merge and old compatibility checks remain incomplete and build skips prior incompatible tasks.

The old alias was temporarily renamed after being backed up, then the previous candidate was tested: Megabonk reached menu and frame telemetry appeared in `Vexa-ThunkGLHost` logcat. Earlier analysis only checked stderr rather than this logcat tag, so absence of stderr lines was not proof no earlier telemetry existed. To test the permanent generator fix, the old alias was restored unchanged and the new APK installed. Megabonk reached menu and gameplay, the old alias was present on disk but absent in the live process maps, the current GL-host hash matched the staged file, and frame telemetry appeared. This demonstrates the new Android loader avoids that specific stale alias on this 64-bit game. It is not full 32-bit or other-games coverage.

The GLX frame sampler records 256 swap-entry intervals with reports every 128 frames; windows overlap. Logcat samples near 12:51 included p50 9.04 ms, p95 13.59 ms, p99 21.56 ms and max 304.43 ms, while other windows differed substantially. Menu, transitions, gameplay and selection UI were not separated by precise markers, so these samples should not be combined or presented as overall gameplay performance. The GL sampler is CPU swap-entry cadence, not physical display or GPU time. `glms/f=0` here is not GPU timing. No controlled FPS A/B has been performed. The separate SDL2 sampler has different non-overlapping semantics and is not loaded by Megabonk.

FEX low-precision x87, JIT disk cache and frame telemetry were explicitly enabled for this launch. Old alias and game saves were backed up at `C:/Users/zeytu/Documents/vexa/logs/megabonk-framefix-20261029/`; it was restored to its original device path to test the generator fix, not deleted. Two save files changed between before and after archives. The game was left at a shrine selection screen. Do not silently restore old saves. Screenshot, logs, and manifests are in the same folder.
